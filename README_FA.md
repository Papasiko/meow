# سامانه ارزیابی عملکرد — نسخه ۲

این نسخه بر مبنای بازخورد سازمان بازطراحی شده است. رابط و APIها برای استفاده در سرور لینوکس و دسترسی از شبکه داخلی آماده شده‌اند؛ پیش از بهره‌برداری عملی، IT باید آن را در محیط آزمایشی نصب و با کاربران واقعی آزمایش کند.

## امکانات این نسخه

- داشبورد مینیمال: بدون بنر آبی «پنل مدیریت»، بدون چهار کارت آماری و بدون فهرست فعالیت‌های اخیر.
- نمودار ستونی میانگین نمره زیررده‌های تکمیل‌شده در ۱۲ ماه اخیر؛ نمره نهایی از ۱۰۰ محاسبه می‌شود.
- فهرست زیررده‌ها با وضعیت، نمره نهایی و نام ارزیاب‌هایی که ثبت نهایی کرده‌اند.
- دکمه Excel در کنار «مشاهده» هر زیررده؛ امکان انتخاب بازه ۱، ۳، ۶ یا ۱۲ ماه.
- مدیریت سؤال، معیار/بارم، نام بخش و ارزیاب مسئول.
- برای هر سؤال، فیلد «دلایل و توضیحات نمره» نگه‌داری می‌شود؛ ثبت نهایی و اصلاح نمره ثبت‌شده بدون دلیل برای سؤال‌های نمره‌دار پذیرفته نمی‌شود. این توضیحات در گزارش Excel نیز درج می‌شوند.
- تاریخ‌های قابل مشاهده در رابط و تاریخ‌های فایل Excel به تقویم شمسی نمایش داده می‌شوند. در پایگاه داده، تاریخ‌ها با قالب استاندارد میلادی نگه‌داری می‌شوند و فرم دوره تاریخ شمسی می‌پذیرد.
- مدیریت کاربران، رمز اولیه، فعال/غیرفعال، سطح دسترسی، بخش کاری و سقف امتیاز اختصاصی.
- هر ارزیاب فقط سؤال‌های اختصاص‌داده‌شده به حساب خودش را از API دریافت می‌کند و فقط می‌تواند نمره همان سؤال‌ها را ثبت کند.
- ذخیره موقت و ثبت نهایی. پس از ثبت نهایی، ارزیاب اجازه تغییر نمره را ندارد؛ API سمت سرور تغییر مدیر را مجاز می‌کند.
- ویرایش سؤال دارای سابقه، در صورت امکان، آن سؤال را نسخه‌بندی می‌کند تا متن و بارم ذخیره‌شده در نمره‌های قبلی تغییر نکند. تغییر سؤال در دوره فعال، وقتی برایش نمره ذخیره شده، مسدود است تا از دو بار شمردن نمره جلوگیری شود.
- دوره‌های جداگانه برای ثبت تاریخچه ماهانه/فصلی و بازه‌های گزارش.
- پایگاه داده SQLite محلی؛ نیازی به اینترنت هنگام استفاده نیست.
- ثبت رویدادهای مهم در جدول audit_log.

## محدودیت‌های مهم و فرض‌های پیکربندی

1. برای ثبت نهایی، مجموع سقف نمره تمام ارزیاب‌های فعال باید دقیقاً ۱۰۰ باشد.
2. مجموع بارم سؤال‌های فعال هر ارزیاب باید دقیقاً برابر سقف امتیاز حساب همان ارزیاب باشد. سامانه اجازه نمی‌دهد ارزیاب ثبت نهایی کند تا وقتی تخصیص نمره کامل شود.
3. کاربران تازه، به‌صورت پیش‌فرض سهم امتیاز ندارند؛ مدیر باید سقف‌ها را در مجموع به ۱۰۰ تنظیم کند. اگر مجموع سهم‌ها ۱۰۰ است، برای افزودن کاربر دارای امتیاز باید ابتدا سهم کاربران فعلی ویرایش شود.
4. ارزیاب در فایل Excel فقط سؤال‌ها و نمرات بخش خودش را می‌بیند؛ مدیر گزارش کامل زیررده را دریافت می‌کند.
5. نمودار ماهانه، میانگین امتیاز زیررده‌هایی را نشان می‌دهد که همه ارزیاب‌های موردنیازشان در همان ماه ثبت نهایی کرده باشند. برای تاریخچه معنی‌دار، مدیر باید برای هر نوبت ارزیابی (مثلاً هر ماه) یک دوره جداگانه بسازد.
6. این نسخه را ابتدا در staging آزمایش کنید. شبکه داخلی جایگزین HTTPS، کنترل دسترسی شبکه، بکاپ منظم و سیاست رمز عبور سازمانی نیست.

## حساب‌های اولیه

- مدیر: `admin` / `admin123`
- ارزیاب‌ها: `evaluator1` تا `evaluator7` / `eval123`

این رمزها فقط برای راه‌اندازی اولیه‌اند. پس از اولین ورود، از صفحه «کاربران و دسترسی‌ها» رمز مدیر و رمزهای ارزیاب‌ها را تغییر دهید. برای ساخت حساب جدید، رمز حداقل ۸ نویسه باشد.

در نصب کاملاً تازه، برای تعیین رمز اولیه می‌توانید قبل از اولین اجرا متغیرهای محیطی `INITIAL_ADMIN_PASSWORD` و `INITIAL_EVALUATOR_PASSWORD` را تنظیم کنید؛ اگر متغیرها تنظیم نشوند، مقادیر آزمایشی بالا استفاده می‌شوند.

## اجرای سرور روی Windows 10 Pro بدون اینترنت

برای سرور آفلاین از راهنمای `README_OFFLINE_FA.md` پیروی کنید. ابتدا روی یک رایانه ویندوزی دارای اینترنت، `prepare_offline_packages.bat` را اجرا کنید تا wheelهای Windows x64 / CPython 3.12 دریافت و ZIP نهایی `OrgEvaluation_Windows10_Python312_OfflineReady.zip` ساخته شود. ZIP نهایی را به سرور منتقل کنید؛ سپس `install_offline.bat` و `run_windows.bat` را اجرا کنید. نصب روی سرور از پوشه `wheelhouse` و بدون اینترنت عمومی انجام می‌شود. رابط محلی `http://127.0.0.1:5000` و بررسی سلامت `http://127.0.0.1:5000/api/health` است. برای دسترسی رایانه‌های دیگر شبکه داخلی، تغییر رمزها، IP سرور و قانون Windows Firewall را طبق راهنما تنظیم کنید. برای نصب‌های آنلاین/پیش‌نمایش روی رایانه شخصی، همین `run_windows.bat` نیز قابل استفاده است؛ اگر wheelhouse آماده نباشد، نصب آفلاین عمداً متوقف می‌شود و به اینترنت عمومی وصل نمی‌شود.

## اجرای آزمایشی روی Linux

```bash
cd org_evaluation_v2
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

برای اجرای مستقیم تستی، برنامه روی `0.0.0.0:5000` گوش می‌دهد. روی سرور واقعی بهتر است IT از Gunicorn همراه reverse proxy و HTTPS استفاده کند و خود Gunicorn را فقط به `127.0.0.1:5000` متصل کند. برای نصب وابستگی‌ها یک بار `./install_linux.sh` و برای اجرای Gunicorn از `./run_linux.sh` استفاده کنید. نصب پیش‌نیازها به اینترنت یا مخزن بسته داخلی سازمان نیاز دارد؛ اجرای برنامه بعد از نصب، به اینترنت عمومی نیاز ندارد.

## متغیرهای محیطی

- `FLASK_SECRET_KEY`: کلید تصادفی و پایدار برای نشست‌ها؛ در production از secret manager یا محیط امن تنظیم شود.
- `EVALUATION_DB_PATH`: مسیر پایگاه داده، اگر مسیر پیش‌فرض `instance/evaluation.db` مناسب نیست.
- `SESSION_COOKIE_SECURE=1`: وقتی برنامه واقعاً پشت HTTPS قرار گرفته باشد.
- `HOST` و `PORT`: برای اجرای `python app.py`؛ پیش‌فرض `0.0.0.0` و `5000`.

## نصب نسخه جدید روی سروری که نسخه قبلی دارد

1. سامانه قبلی را متوقف کنید.
2. از پایگاه داده و کلید نشست بکاپ بگیرید:
   ```bash
   python3 backup_db.py
   cp instance/.secret_key backups/secret_key_backup 2>/dev/null || true
   ```
3. فایل‌های `app.py` و `templates/index.html` و `requirements.txt` را به‌روز کنید؛ فایل `instance/evaluation.db` را حذف نکنید.
4. پیش‌نیاز `openpyxl` را نصب کنید، سپس سامانه را در محیط staging راه‌اندازی کنید. کد مهاجرت در startup سعی می‌کند حساب‌ها، زیررده‌ها و نمره‌های نسخه قبلی را نگه دارد، اما قبل از هر ارتقا بکاپ ضروری است.
5. ورود مدیر و ارزیاب، قفل ثبت نهایی، گزارش‌های xlsx و سابقه نمره‌ها را آزمایش کنید.

## بکاپ

هنگامی که برنامه در حال اجراست، از روش SQLite backup استفاده کنید:

```bash
python3 backup_db.py
```

پوشه `instance` شامل پایگاه داده و کلید نشست است؛ هر دو باید حفاظت و بکاپ امن داشته باشند. پایگاه داده یا `.secret_key` را در مخزن عمومی یا فلش غیررمزشده نگه ندارید.

## آزمون نسخه تحویلی

در محیط بسته‌سازی، کد Python با `py_compile`، اسکریپت JavaScript با Node syntax check و الگوریتم تبدیل تاریخ شمسی با آزمون‌های رفت‌وبرگشت تاریخ بررسی شدند. مسیرهای اصلی ثبت نمره، الزام توضیح، ساخت پایگاه داده و خروجی Excel نیز با یک آزمون محلی آزمایش شدند. اجرای واقعی فایل Batch ویندوز در این محیط لینوکسی ممکن نیست؛ برای بررسی نصب و اجرای Windows، از `verify_windows.bat` و سپس نشانی سلامت بالا روی رایانه ویندوز استفاده کنید.


## دیتابیس ارسالی کارفرما
در این بسته، `instance/evaluation.db` نسخه‌ای از دیتابیس ارسال‌شده برای آزمون و استقرار اولیه قرار دارد. پیش از اجرای نسخه روی سرور عملیاتی، از دیتابیس مقصد نسخه پشتیبان جداگانه تهیه کنید. فایل `.secret_key` قبلی در بسته قرار داده نشده و برنامه در اولین اجرا کلید جدید تولید می‌کند؛ بنابراین کاربران باید دوباره وارد سامانه شوند.
